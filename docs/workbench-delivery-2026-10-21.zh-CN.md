## 3. 发布状态与可靠性

本轮保留 Supabase、现有队列与账号串行执行域，不引入第二个业务状态库或调度所有者。

- 预检与执行重新核对内容修订、目标账号、媒体和交付方式；排期进入 fingerprint 与持久批次输入。
- 同一内容、同一账号在一个批次内只能选择一种交付方式。稳定命令 ID 与数据库批次实现重复请求复用，刷新和重试不会仅因前端状态丢失而创建第二份交付。
- 相同内容已有不同时间或不同交付方式的待办时明确拒绝静默覆盖。需先处理或取消尚未提交的任务，再重新审核；已受理、正在提交或结果未知的任务保留原事实。
- 文章与视频共享交付意图检查；账号忙只推迟该账号，其他账号仍可扫描；提交与结果核验各自尝试，不以清除屏障恢复运行。
- 已存在远端标识、上传 journal 或未知提交结果时先核验，不自动重发。取消本地任务也不代表可以忽略仍存在的上传 journal。
- 公开发布以平台标识、匹配的作品链接和确认结果为依据。平台草稿、Postiz 草稿、人工待办、排队与上传完成分别保留各自状态。

这些可靠性检查已纳入本轮回归与隔离验证；它们不意味着每个平台账号已经获得写入权限或通过真实公开发布测试。

## 4. 运行诊断与 48 小时观察

“设置 → 诊断日志”提供服务和级别筛选、分页、刷新与当前筛选导出。日志采用本地 NDJSON，保存在既有 data bind root 下；每个进程独立文件，按 1 MiB 或 24 小时切段，按 14 天 / 32 MiB 中较先达到的限制保留。检索跳过并报告损坏行，不因收集失败阻断正常业务。

日志使用固定事件和字段白名单：时间、事件 ID、服务、级别、请求 / 工作关联 ID、HTTP 状态、耗时与固定错误码。接口不接收任意文件路径，不导出正文、请求体、凭据、Cookie、环境变量或原始异常。导出最多 200 条当前筛选结果，不等同完整原始日志归档。当前关联工作 ID 可能是 operation 或 run ID，不应一概解释为发布 job ID。

持续运行观察由现有 API 进程托管，通过 GET 读取状态，POST 显式开始或停止；不需要 host 常驻脚本、分离子进程或新增持久容器。界面根据运行状态显示开始 / 停止按钮，并防止重复提交。

每次开始新观察都创建独立窗口，旧窗口时长不会累加。API 重启造成失去所有者的窗口、超过 freshness 阈值的采样，均按中断处理；重启不会自动续算。通过状态要求当前 workspace 与 release 匹配、墙钟和单调时钟均达到 48 小时、达到要求采样数及就绪检查完整。**本轮验证了这些判断和生命周期，并已通过界面启动 v20 的独立观察窗口；当前尚未完成连续 48 小时观察。** 运行观察只证明运行就绪性，不替代内容质量、真实平台发布和生产验收。

## 5. 插件与更新方式

本轮已实现的插件方向包括采集 / 待处理 / 账号入口、采集会话与稳定命令恢复、独立连接状态和恢复、分页搜索、执行后刷新实际状态，以及与 Web 一致的产品名称、中文状态和版本信息。待处理未知结果必须先核验，不能因 popup 重开、连接重建或版本更新而重放写入。

实际指定 Chrome profile 已核对，插件 **2.0.12 已激活**。安装 ZIP、源码 ZIP、公开下载与固定安装目录均已同步；在线下载 hash 与最终容器产物一致。实测插件内“已替换文件，重新加载”后，仍显示版本 2.0.12、旧测试端口离线和“草稿写入已暂停”的明确原因，未知记录继续保留。当前工作台绑定的是旧“文章同步助手”扩展 ID，品牌插件属于另一扩展身份；本轮没有重新配对、迁移账号绑定或恢复真实草稿写入。

| 安装方式 | 更新流程 | 本轮边界 |
| --- | --- | --- |
| Chrome Web Store 安装 | 需要本产品完成商店发布、维护同一产品身份和版本；Chrome 检查并分发更新；可用更新在安全时机提示应用 | 本产品尚未上架，不能承诺现有安装已经获得商店自动更新 |

没有实际执行且持久存储可读时，允许更新或修复 managed 连接并保留未知 journal；活动执行或无法读取持久记录时禁止维护。未知或损坏记录继续阻止任何新的草稿写入，同 payload 的既有完整回执可读，模式切换仍使用严格检查。主界面持续显示写入暂停原因，托管菜单只打开任务助手，重复安装事件不再重复创建菜单。恢复保护已通过模拟与真实 Chrome 重载验证；未知结果的权威核对和旧平台绑定迁移仍需完成，操作步骤见 [账号记录](accounts.md)。
