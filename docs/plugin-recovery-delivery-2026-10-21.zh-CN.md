## 已修复的 review 问题

| 问题 | 修复与验证 |
| --- | --- |
| 平台已写入但插件回执丢失，升级后无法安全恢复 | 增加 `studio.journal` 和 `studio.confirmReceipt`。先在原任务登记实际平台回执，再显式同步到插件。核对完整原请求摘要、原账号、原素材、草稿 ID 与编辑 URL；只更新原日志，不再次调用写入器。 |
| 未知结果可能被新任务绕过 | 工作台预检和插件执行器同时检查日志；未知记录在任务增加执行次数之前阻止新写入。其他工作区的记录同样保留。 |
| 相同配对再次保存会改变私密地址 | 相同扩展 ID 和 Token 幂等返回原连接；迁移配对保留账号与历史记录。 |
| 浏览器 WebSocket 错误可能记录带密钥的 URL | 新客户端通过受限子协议传递配对凭据，实际连接 URL 不含密钥；保留旧客户端到新服务的兼容入口，拒绝多凭据和歧义请求。知乎日志不再输出平台响应正文。 |
| 平台只返回 authenticated=true，却没有账号 ID | 拒绝绑定和保存，明确返回 `identity_incomplete`。已在当前公众号检查中验证。 |
| 地址输入过程中自动保存，可能误断开连接 | 改为明确的“保存连接地址”，显示保存结果，阻止重复提交；补齐设置关闭按钮的无障碍名称。 |
| 当前登录身份可能覆盖旧账号 | 显示身份不同的警告，新增账号与更新原绑定分开；本轮没有修改原“孔涛”绑定。 |
| 开发验收面板占据日常账号页 | v22 从日常账号流程移除浏览器 fixture 面板；开发组件和测试接口保留。 |
