# 文章流程、独立视频与 OrbStack 实施说明

日期：2026-10-15。本文记录本轮代码边界；实际运行证据见本文末尾及 [Kubernetes 操作说明](orbstack-kubernetes.zh-CN.md)。阶段二仍受本地验收门槛约束。

## 产品流程

主导航为「发现热点 → 内容生产 → 内容分发 → 执行历史 → 内容管理」，另有独立视频工作区和设置。页面 URL、详情选择和筛选由 React Router 管理；TanStack Query 只缓存服务端查询，编辑缓冲单独保存。未保存的修改通过统一导航保护保留。

发现热点的常用配置只有关注要求、地区、时效、问题数；多个关注配置各自保存。执行时间、模型、来源、目标平台、资料与图片置于相关配置。立即执行与定时执行使用同一任务配置。来源 URL 和已有资料进入现有研究流程，来源不足或编辑范围不符时不强行生成。热点问题可以单独或批量创建内容任务，沿用冻结证据；历史运行复制为可编辑的一次任务，默认关闭调度，修改不会覆盖原任务和原批次。

内容分发集中展示各个平台版本。同步草稿与公开发布是不同命令，支持单篇、批量及账号选择。每个目标单独返回结果；部分失败不会覆盖成功结果。定时任务只能自动生产及同步已选账号的草稿；公开发布仍要求具体修订与账号的审批。未知结果先核验，不能自动再次提交。内容管理仅查询，按类型、平台、任务、批次、时间及历史交付状态筛选，并可跳转原工作区。

X 热点内容保留真人发布边界；Product Hunt 使用真实产品上线资料；YouTube 社区文字不等于视频上传；B站专栏连接不等于视频连接。当前连接能力以接口返回和实际账号授权为准，不能把手动入口称为自动同步。

## 代码与数据边界

- `src/contracts`：浏览器可用契约和安全投影类型；现有纯 Zod 模型逐步复用。浏览器配置没有 Node 类型，导入边界回归拒绝执行模块进入前端。
- `src/client`：校验响应的 HTTP 客户端，查询取消只取消请求，不取消持久任务。
- `src/application/workspace.ts`：查询、热点转任务、历史复制和批量分发用例，不依赖 React、路由或组件。
- `src/core`：既有业务、版本、账号互斥与基础设施适配；`src/server/*-api.ts` 做校验和 HTTP 映射。
- `infra/k8s` 与 `scripts/kubernetes*`：部署和生命周期适配，复用业务执行器及唯一 pgmq/pg_cron，不增加业务 CronJob 或新数据库。

工作区摘要、内容列表、任务列表、执行列表与单篇详情分开读取；分页使用 `created_at + id` 游标。新页面不加载完整 workspace。文章媒体使用稳定引用，视频媒体使用 `projectId + renderId` 的受控 URL。历史查看和下载不创建修订、不补写导出。旧接口保留兼容，部署内部根路径不参与页面设计。

文章提交由 `studio_commit_article` 原子更新当前稿、不可变修订、命令回执及后续适配/导出任务。已有 proposal 事务继续复用；工作区修订触发器也保护旧调用链。相同命令重试返回原修订，不新建重复历史。素材先进入 LocalFS，再提交引用；导出失败留在可恢复操作中，不删除已提交稿件引用的素材。导出使用原子文件写入；旧修订的完整文件不重写，冲突字节保留并报错。将来改变导出格式须提升导出器版本并使用独立目录，不能重算旧快照。

本轮没有拆分全部旧 workspace JSON，也没有增加第二套媒体权威。历史查询以 Supabase 修订为准，原文件和旧 objectKey 继续兼容读取。

## 视频

VideoProject 增加可选 targets 与 renderApprovals，旧项目不做读时批量回填。共享内容修订包含脚本、分镜和制作设置；平台目标分别保存账号、文案、标签、成片及交付设置，并各自递增修订。共享内容变动后提示重新复核，保留原文案与旧成片。某目标未知提交只保护该目标和引用成片，允许维护其他目标。

V2 渲染输入 hash 包含实际内容与制作设置；平台文案、账号与 UI 状态不进入 hash。同设置复用成功输出，横竖版分开渲染。新项目默认 1920×1080；旧项目保留既有尺寸。V1 hash、审批和历史输出保持原算法。视频不再为平台分别复制 MP4。

YouTube 继续使用既有官方 OAuth、可恢复上传 journal 与远端回读，V2 审批绑定目标账号、平台文案修订、成片字节和上传设置。私密/不公开上传记录为 delivered，公开确认后才是 published。B站当前没有经验证的官方视频适配器与应用授权，自动能力关闭；可下载成片、字幕并复制平台文案完成原生投稿。

## 上游选择及适用范围

[OrbStack 官方](https://docs.orbstack.dev/kubernetes/)确认单节点、共享镜像引擎及默认本机服务访问；使用固定镜像 tag 和 IfNotPresent。[Supabase 自托管说明](https://supabase.com/docs/guides/self-hosting)是继续保留 Compose 数据库的依据；本轮不迁移数据库拓扑。[YouTube 官方续传协议](https://developers.google.com/youtube/v3/guides/using_resumable_upload_protocol)支持断点与状态核对。B站权限须在[官方开放平台](https://open.bilibili.com/)完成验证，门户可访问不代表已获得投稿接口授权。

本轮仅新增 Query/Router 两个职责独立的稳定依赖，继续复用 Zod、pgmq/pg_cron、Kokoro、FFmpeg、现有 prepared-media 和平台连接。无需 Helm、Operator、Redis、独立 PostgreSQL 或另一套工作流系统。

## 执行证据

以下为已执行结果；平台准入和长期运行门槛继续单独记录。

- 严格 Node／浏览器 TypeScript 与生产构建通过；全仓 370 项测试，369 通过、0 失败、1 个历史 macOS 测试跳过。最后的运行归属、进程健康和备份相关回归及 Kustomize 实际 server-side 校验通过。
- 新迁移 018–024 已先在回滚事务验证，再经加密备份后应用。SQL 回归实测原子修订／回执、重复命令、平台发布历史隔离、热点父任务及批次关联、只读查询，以及 proposal 接受与重复提交只产生一次后续适配；账号 lease／未知结果／旧 owner 提交回归通过，均回滚 fixture。
- 最后增量复核修复旧格式稿件应用 AI 建议时后补 document／规范化导致冻结快照不匹配、后续适配丢失所选模型，以及运行 checkpoint 暴露 baselines 路径的问题。真实 Supabase 的隔离 smoke 通过完整 applyOperation 链路，确认无 document 稿件、原始 proposal、模型及生成要求、唯一 sync 后续任务、重复应用和清洗投影；自建工作区及六张关联表已清理，无模型、worker 或平台提交。
- 迁移前格式 3 加密备份包含 1,062 个已核验文件，已恢复到独立 Compose；原 3 个工作区，以及文章修订和视频内容的 workspace hash 一致，未恢复平台或模型授权。
- Kubernetes 中实际 Supabase／pgmq 配合确定性研究、模型和扩展 fixture，跑通热点晋升、失败恢复、知识快照、不可变导出及三平台草稿回执；master 生成一次、失败目标重试一次、重复写入零、公开作品零。随机 fixture 工作区已清理。这不冒充真实平台或模型授权验收。
- 真实 Kokoro／MPT／FFmpeg 横竖版渲染、完整解码及下载 hash 通过；API Pod 重建保留 Tus 半传位置。渲染进行中终止 worker，旧上游迟到成功但未晋升；实际租约到期后新 owner 接管同 render，attempt 1→2，复用 9 个阶段并完整解码。没有手工缩短租约或修改 DB 时间。
- v4 浏览器验证五个文章入口、批次／平台过滤、视频分页与详情、独立平台文案、历史修订及未保存保护。无 document 的旧格式稿件清洁打开不修改数据；仅改知乎标题后原稿逐字未变、未新增 document、其他平台不变、不触发 AI 适配。浏览器控制台无 warning／error。
- v5 完成 K8s → 同版本 Compose → K8s，文章、视频和投递哈希一致，保留 5 篇原文章、6 条原投递、2 个视频项目。首次回退暴露依赖重建及 Kong 旧 DNS 问题，已改为 `up --no-deps`，纠正后的往返没有重建任何 Supabase 服务。Compose API／worker 也改用实际 readiness 检查。后续修复以新固定版本 v8 采用，实际状态见最新验收记录。
- K8s 停止所有应用后创建格式 3 加密备份，1,065 个文件核验通过。恢复到独立 Compose 后，4 个工作区、文章／视频／命令回执以及 868 个权威业务文件 hash 一致，2 个未知投递屏障保留；只启动恢复 API 验证就绪、列表、详情、受控媒体及 SPA 深链接，随后停止恢复实例并保留数据。默认没有恢复授权，没有启动恢复 worker。

运行归属使用私有标记及实际 Pod 停止结果：K8s 接管时 Compose start 被拒绝，活跃 K8s 下旧 Compose backup／stop／migrate 被拒绝。同 release 镜像可切回 Compose；隔离恢复自动重置为 Compose/stopped，保留镜像组合。最终切换、切回、再采用及新运行备份恢复结果另见 [最新验收记录](acceptance.md)。
