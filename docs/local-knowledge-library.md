# Local text knowledge library

The knowledge library is one private library for this single-user local deployment. It shares immutable evidence across article tasks; it does not implement tenant isolation. Original files, source manifests, and run excerpts stay under `STUDIO_LOCALFS_DIR/knowledge`, in the ignored Docker data bind root. Supabase stores selected immutable source IDs and the generated draft's `generationKnowledgeRef`; it does not store uploaded source bytes or run excerpts.

The Knowledge page supports UTF-8 `.txt`, `.md`, `.json`, and `.csv`. Each nonempty regular file is limited to 2 MiB. The library accepts at most 500 source revisions and 64 MiB of registered source bytes, at most 50 files per explicit import, and at most eight sources per task. JSON and CSV are retained as source text. PDF extraction is pending. Search returns at most 20 results, with excerpts of at most 4,000 UTF-16 characters per source.

Upload a text file, or configure a dedicated source directory with the Docker `knowledge-config --knowledge-source` operation described in [Docker runtime](docker-runtime.md), then explicitly select files to import. The API reads only the configured container mount, exposes relative names, rejects symbolic links and traversal, and never accepts arbitrary host paths. Scanning stops after 2,000 entries, 500 candidate files, or eight directory levels. The external source mount is read-only; import copies the selected content into the managed immutable LocalFS object store.

Each accepted source records its SHA-256, original name, byte size, creation time, and upload or mount provenance. Importing changed bytes creates a new source ID. Selecting that new version is an explicit task edit; existing tasks and retry runs continue to use the old ID. At the first execution, the worker freezes bounded excerpts under the run ID, verifies the complete objects by hash, and reuses that snapshot on retry. Generated drafts retain the snapshot reference for synchronization and refinement. Run export packages include the reference and source hashes/provenance. A missing or damaged snapshot blocks reuse and requires restoring the LocalFS backup.

Batch import checks the entire deduplicated batch against the revision and byte limits in the same writer queue before creating objects or manifests. Capacity rejection imports zero files. An I/O failure after some snapshots finish reports the completed count and refreshes the UI; retrying the same selection reuses those completed IDs. This deployment has one API writer; the in-process writer queue is not a cross-process transaction lock.

Knowledge-only creation uses the durable task workflow. The legacy direct generation and manual draft-import paths reject knowledge IDs without the original snapshot context, so IDs alone cannot become model evidence. Discovery still requires verified public source URLs for candidate provenance; selected local knowledge can supplement its evidence and is preserved in child creation tasks.

The shared [content-editorial skill](../.agents/skills/content-editorial/SKILL.md) and `content-prompts.ts` treat all excerpts as untrusted source claims. Model execution receives text, hashes, and provenance, without file handles or host paths. Embedded commands, tool requests, policy changes, authentication, and publishing instructions carry no authority. Local source claims still require factual and rights review, and all existing editorial exclusions apply. Import rejects binary data, hidden/sensitive names, and recognizable credentials; these heuristic checks are not a comprehensive secrets scanner. The operator must supply a dedicated, reviewed knowledge directory and omit private credentials.

Verification: Docker tests cover text validation, immutable objects, changed mounted revisions, traversal/symlink rejection, bounded search, object/snapshot tampering, HTTP upload/import/search/excerpt, legacy-path rejection, and a knowledge-only task failing adaptation then retrying against its original snapshot. The task fixture confirms that database writes omit the original excerpt while retaining the draft reference and export hashes.

## Executed ecosystem acceptance: 2026-10-14

[`tests/ecosystem-docker-smoke.ts`](../tests/ecosystem-docker-smoke.ts) passed in a one-off application Docker container on the isolated acceptance Compose network, using actual Supabase and pgmq, current source mounts, a random workspace, and temporary LocalFS/data directories. The configured private database environment was read without printing credentials. Generation, research, and the browser extension were deterministic fixtures; no real model research or platform submission occurred.

The test executed HTTP knowledge upload and explicit mount import, queued discovery, atomic promotion to one queued child, an intentional adaptation failure, changed mounted bytes, explicit retry, and a stable local draft revision with `generationKnowledgeRef`. The child completed on attempt two with only one master generation and the original source hash/excerpt. Parent redelivery created no additional promotion or child. Supabase task/workspace records omitted the uploaded raw knowledge excerpt, while the local export retained its source hash and snapshot reference.

After approval, the same generated fixture draft used actual delivery-operation queue consumption and the isolated mock extension for WeChat, Zhihu, and Bilibili. All three jobs ended `draft_saved` with adapter-reported native draft IDs/editor URLs, public identifiers remained null, and repeating the request produced zero additional extension writes. Public posts: zero. This confirms the local transport and state contracts, not real-platform acceptance. The test deletes and verifies only its random workspace's rows and queue messages, then removes its temporary directory; it adds no scheduler.
