# 来源权重与证据生产流水线 v2

实施日期：2026-10-17。新建或显式选择 `pipelineVersion=2` 的文章和发现任务使用此流程；历史任务、视频域和历史审批不改写。实现已进入隔离验收，**尚未达到生产放行条件**。

## 来源与任务

知识库页面提供 18 个默认发现入口：GitHub Changelog、DeepSeek、Qwen、Ars、The Verge、IEEE、少数派、InfoQ、MIT Technology Review、Product Hunt、HN、arXiv、Crossref、Stack Overflow、人民网科技、WSJ、SCMP、受限 Reddit。可增加网站、栏目、RSS/Atom、GitHub Releases、文章链接、HN 和 Crossref 来源。目录条目不代表实时可读性或数据许可。

每个来源权重 1–5，默认 3。先过滤主题和日期，再按最大余数法分配 70% 指定来源预算和 30% 开放补证预算；实际候选抓取名单也应用配额，无相关结果可以转移名额。预算指应用查询任务、候选和页面数，不声称控制 Codex 内部每次检索。任务覆盖不改全局权重，运行保存配置快照，重试复用原配置和已完成阶段。

官方更新每小时、普通订阅每小时、论文每日检查，可分别调整。来源采集复用 pg_cron → pgmq → 文章 worker 的队列、租约和幂等机制。没有第二个调度引擎。任务默认中文、48 小时时窗、14 天历史去重；每批最多 3 篇，缺证可以零产出。定时任务启用前仍须设置时间、主题、模型和平台。

Codex 内建 live web search 是默认路径；不需要外部搜索 Key。Tavily 适配器仅在明确选择并配置 `STUDIO_TAVILY_API_KEY` 时调用，其 HTTP 请求不计作模型调用；Exa 和 Firecrawl 尚未接入，不显示为可用能力。Reddit 不执行未批准采集，Product Hunt 使用公开 RSS 做发现；搜索摘要、付费墙导语和 RSS 时间不能替代正文或发布日期。

Google Trends 进入网页任务的持久化发现路径，仅使用实际支持地区的 RSS。观测不是全网排名。不支持地区保留普通研究路径，不编造其 Trends 数据。研究阶段不因继承摘录或已有知识快照提前返回。

## 自动生产与质量门

流程为：来源收集/知识检索 → 研究规划 → 定位证据/事实清单 → 有限补证 → 主稿 → 独立事实与编辑审校 → 有限修订 → 平台改写/复核 → 绑定修订的质量报告。发现任务另外执行事件聚类、原始出处保留、历史去重和自动创建文章任务。

模型角色使用独立上下文，沿用一个已授权执行器及并发 1；没有增加模型订阅。基础文章最多 12 次模型尝试，每个平台适配和复核合计最多 2 次；重试计入。每次模型调用最长 10 分钟，补证与成稿修订各最多 2 轮。v2 关闭额外格式修复，不能绕过额度。429/额度等待复用原 pgmq 消息和检查点，不重新调用已完成的阶段。

程序检查精确引文及片段成员、关键数字和版本、厂商性能归因、社区观点、预印本限制、真实测试记录、引用 URL 和平台事实边界。语义支持、原创价值与标题兑现由独立模型上下文辅助审校；界面不声称“AI 证明事实为真”。研究缺口只包含兑现读者承诺所必需的问题，未取得的可选断言必须省略；影响拟写或必需断言的矛盾继续阻止产稿。

质量报告绑定正文/平台稿 hash、来源版本和稿件 revision。编辑使旧报告失效。一般报告有效 7 天，价格/权限/配额等时效断言有效 24 小时；准备交付时，超过 5 分钟未确认的时效来源重新读取并比较 hash。过期或变化自动创建新的研究运行，更新同一文章的下一修订并清除旧审批；每个旧修订只排队一次。并发人工编辑通过 CAS 保留，旧运行不能覆盖。新修订审校完成前阻止交付。

公开发布由人工操作；v2 禁止任务级 automatic 公开发布。已授权的草稿连接仍使用现有账号、修订、授权和不确定提交保护，不把本地稿件或队列成功称为平台发布。

## 统一证据层

原件、标准正文和阶段产物存 ignored LocalFS 的内容寻址 `evidence/`，使用 SHA-256、原子写入和读取校验。Supabase 保存关系、索引、状态、稿件修订权威。生成文章不会成为事实来源；既有文本可以显式索引，网页收藏、PDF 和真实测试记录分别导入。

网页保留标题路径、实际站点、原署名来源、日期和正文位置。按相同结构合并相邻段落，约 350 token/50 token 重叠；中文按字符估算，表格保留表头。分块版本 `cjk350-v3`。混合检索用中文分词、tsvector/pgvector 和 RRF，限制每份文档的占位；排除旧 URL 快照、合并同源正文，优先完整一手资料。混合中英文问题另外保留最多两份匹配英文产品名称的外文原文。定位片段按相关性选择，证据上下文有总量上限，不静默只取文章开头。

向量模型固定为 `intfloat/multilingual-e5-small@614241f622f53c4eeff9890bdc4f31cfecc418b3`，384 维、归一化，`query:`/`passage:` 前缀。模型或分块升级需要重建索引。

PDF 最大 50 MiB/200 页。Docling 2.140.0、RapidOCR CPU 在本地处理；按物理页分别转换，避免旋转扫描件的页码合并。保留 UTF-16 位置与表格，低置信度/不完整转换拒绝入库。表格数字和低质量 OCR 数字标记待核对，不能自动支持数字断言，需要真实人工执行记录补证。单页解析预算 60 秒，总处理窗口有界。短于 80 字的抽取不作证据。

`services/knowledge/uv.lock` 固定依赖，`models.lock.json` 固定 54 个模型文件的 SHA-256；构建只导出这些文件，不带下载缓存。运行时断开模型在线下载，不挂数据库、模型账号或发布凭据。CPU=2、内存上限 4 GiB，单并发。k 的隔离 K8s 向量请求后观测约 699 MiB，Compose 完成 PDF 后进程约 2.9 GiB；这是小样本观测，不代表最大 PDF 压测结论。

## 接口与页面

- `/api/sources`：目录、全局配置、来源探测和增量采集。
- `/api/evidence/search`、`documents`、`web`、`pdf`、`test-record`、`index-knowledge`：检索、原件及导入。原件下载固定为附件，不执行存储 HTML。
- `/api/runs/:id/evidence`：研究计划、阶段尝试、证据和选题/跳过理由。
- `/api/drafts/:id/quality`：修订绑定的主稿及平台质量报告，可点击事实查看原文位置。
- `/api/production/metrics`：来源失败、合格稿、补证、耗时、时效和已确认用量；未知费用保留 null。

Host/Origin 检查、工作区隔离、来源 URL 凭据与内网访问防护继续生效。知识库与任务页面新增来源配置，执行历史新增阶段和生产观测，编辑器新增证据报告。

## 部署

增量迁移为 **026–032**：证据/来源、时效确认、去重、查询召回、修订刷新、跨语言检索和向量版本隔离。现有 owner 数据库尚未应用这些迁移。先在隔离工作区验收，再按 [Kubernetes 切换流程](orbstack-kubernetes.zh-CN.md) 备份、停止应用、迁移和部署。不能在同工作区同时运行 Compose 和 K8s 应用，也不能跳过现有采用/回退门槛。

构建知识镜像：

```sh
sh scripts/docker.sh knowledge-build --root "$STUDIO_BIND_ROOT" \
  --image content-studio-knowledge:20261017-evidence-v7
```

构建前要求项目文件系统至少剩余 15 GiB。默认使用官方 PyPI；网络受限时可显式设置已审阅的 `STUDIO_PYPI_MIRROR=https://pypi.tuna.tsinghua.edu.cn` 和 `STUDIO_APT_ORIGIN=https://mirrors.tuna.tsinghua.edu.cn`。镜像只改变传输位置，版本及官方 wheel hash 不变。

Compose 使用 `evidence` profile 的 `knowledge-tools`，以固定的 `STUDIO_KNOWLEDGE_IMAGE` 选择构建版本。私有 `config/compose.env` 使用 JSON 字符串格式；已有 `runtime-orchestrator.json` 的实例还要同步其中的 `images.knowledge`，该标记是实际运行版本的权威。配置后 `docker.sh` 的启动、状态、停止和备份自动包含 evidence profile；旧实例没有该配置时维持原服务集合。

K8s configure 保留原 root/node/workspace/context 参数，增加 `--knowledge-image`；默认旧配置仍为八服务，新配置加入第九个内部服务。知识服务请求 1 GiB/0.5 CPU，上限 4 GiB/2 CPU。正式切换仍执行现有预检、备份和 cutover 门槛，不能直接 apply 绕过调度者与迁移保护。

跨 Docker 引擎装载镜像使用带余量和根文件系统启动探针的脚本：

```sh
sh scripts/load-runtime-image.sh --source "$SOURCE_DOCKER_CONTEXT" --target orbstack \
  --image content-studio-knowledge:20261017-evidence-v7
```

装载前保留 8 GiB 加两倍未压缩镜像大小的磁盘余量。Docker 返回“Loaded”不能单独证明根文件系统可运行。

本次 k 的 OrbStack 镜像快照损坏，普通装载仍引用缺失父快照。隔离知识服务使用显式 `evidence-v6-rehydrated` 标签恢复，原始构建镜像保留。通过 Docker 支持的 [export/import 配置恢复](https://docs.docker.com/reference/cli/docker/image/import/) 重建文件系统后，服务代码和完整模型 manifest hash 与原构建一致；没有重置引擎、删除卷或复制账号。该现场恢复标签不替代正常构建版本和验收门槛。

当前隔离实例为 `.docker-evidence-acceptance`，网页地址 `http://127.0.0.1:15731`，使用独立 Supabase/LocalFS，暂停调度、无发布账号与发布作业。API 与文章 worker 固定 `20261017-evidence-v12`，知识镜像固定 `20261017-evidence-v7`；模型复用 owner 已授权的 `content-studio-model:20261015-review-v9`，不复制账号。`config/images.lock.json` 保存五个应用镜像及六个 Supabase 镜像的不可变身份。此次知识镜像在已校验依赖与模型锁的原镜像上仅更新服务代码，三个真实 PDF 已用最终镜像重新检查。

2026-10-18 完成引擎迁移后，隔离 Compose 通过 OrbStack 内 Kubernetes 的模型服务 ClusterIP 直接复用 owner 已授权模型，不依赖宿主机 18910 端口转发。该地址记录在私有运行配置中；重建 Service 时需同步实际地址。隔离 K8s 知识探针已停止，没有与该 Compose 工作区并行运行。
