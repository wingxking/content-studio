# 插件配对迁移、草稿核对与交互修复 Coding Spec

日期：2026-10-21。基于工作台 v20、插件 2.0.12，延续 [工作台规格](workbench-coding-spec-2026-10-21.zh-CN.md)。目标版本为插件 2.0.13；实际部署、真实平台结果和剩余人工事项以交付记录为准。

## 目标与边界

迁移的是连接身份，不静默改写平台账号、原审批、原草稿任务或未知执行记录。插件从旧测试端口恢复到现有工作台后，可读取状态、核对当前账号并处理已确认的回执；缺少结果时继续暂停草稿写入。保存草稿和公开发布保持独立，本轮不调用公开发布接口。

同一配对的重复保存不轮换密钥或断开健康连接；扩展 ID 或密钥变化才生成新配对。迁移前保留私密配置备份，迁移后分别检查桥接身份、平台稳定用户 ID 和历史账号绑定，不能仅凭昵称推断同一账号。

## 技术选型

保留现有 MV3 service worker、双 WebSocket 通道、Supabase/pgmq、账号租约与 LocalFS。新增迁移、持久服务、队列引擎和第三方依赖均为 0。新能力通过 v1 hello 的可选 `features: ["journal-reconciliation"]` 协商；旧客户端不宣告该能力时，不假装支持核对同步。

配对地址仍由本机服务生成并以密码输入框显示。2.0.13 在实际 WebSocket 建连时将密钥放入 `Sec-WebSocket-Protocol` 握手字段，连接 URL 只有 `/connect` 或 `/ui/connect`，避免 Chrome 连接失败日志记录密钥。服务端继续校验精确扩展 Origin、配对密钥及现有双向握手；支持旧版 query-key 握手，但拒绝同时提供两种凭据、多个协议或无效格式。业务方法分派依据经过校验的配置身份，不能因传输 URL 去除 query 而误入独立模式。

## 核对协议

| 方法 / API | 行为 | 保护条件 |
| --- | --- | --- |
| `studio.journal` | 读取 pending job ID、blocked、invalid；不返回原文或凭据 | 现有已认证本机桥；上限沿用 2,000 条 journal |
| `studio.confirmReceipt` | 同步已人工核对的原草稿回执，保留原 requestHash，并记录 operator_verified 时间 | 完整请求 hash 与原记录一致；草稿平台/ID/URL 校验；当前平台稳定用户 ID 与原 execution 相同；无活动写入 |
| `GET /api/publishing/draft-connectors/pending` | 将插件记录与当前工作区原任务连接，返回标题、状态和可执行下一步 | 外部工作区只显示待核对 ID 和说明，不能借当前工作区覆盖它 |
| `POST /api/jobs/:id/draft-receipt/sync` | 用不可变原快照重建请求，发送核对同步；不调用平台写入 | 原 job 是 native draft_saved，已有 operator_verified 平台回执；持有原账号 reconciliation 租约；原素材 hash 不变 |
| 原 `POST /api/jobs/:id/draft-receipt` | 保留原有人工核对事实登记 | 不自动清空插件 journal；另以已确认回执执行同步 |

同步的真实含义是“操作人已核对原草稿，工作台与插件记录一致”，不伪装为平台独立自动验真。同步失败时保留工作台已登记的事实与插件未知记录，可使用相同原请求重试同步；不能重试平台创建。已完成且相同的回执同步幂等，完整相同请求重放仅返回原回执。不同内容、账号、草稿链接、任务或损坏 journal 均拒绝。核对一条不能解除其他未知记录的屏障。

新版插件宣告核对能力后，原生草稿预检和最终发送前都会读取写入屏障。被屏障阻止时，不能先增加尝试次数再把一个根本未发送的新任务误标为未知。

## UI 改变

1. 插件私密连接地址改为明确的“保存连接地址”表单；输入中不自动改地址，保存期间防止重复提交。成功、失败、记录保留分别显示。
2. 连接设置提供可访问的关闭按钮，修复抽屉高度与滚动；独立模式高级设置继续折叠。
3. Web 配对区区分首次连接与“修复或迁移插件连接”；变更扩展 ID 时说明原账号绑定和未知记录保留。
4. “平台与账号”显示插件待核对记录。支持直接打开当前工作区原任务，或同步已人工核对回执；其他工作区与损坏记录显示具体恢复说明。
5. 原任务中，已人工核对的 native 草稿可同步回执到插件；按钮明确说明不再次发送草稿。
6. 知乎适配器错误仅记录 HTTP 状态与固定提示，移除原始响应正文，避免草稿内容和平台响应进入日志。

## 验收

- 配对重复保存稳定，真实迁移连接成功后仍保留旧平台绑定。
- 丢失本地回执后，同一已核对回执可以同步、重放和再次同步，平台创建次数保持一次。
- 变更 payload、平台账号、URL、job ID、会话失效、损坏记录和其他未核对记录继续拒绝；不会调用草稿写入器。
- 新握手的两个通道均能连接，实际 URL 不含密钥；旧版握手仍有效，歧义输入拒绝。
- 主程序严格类型检查与回归；插件锁定安装、类型检查、构建、打包、真实 Supabase/pgmq/扩展协议隔离链路通过。
- 真实平台必须分别打开原草稿核对正文与账号。本轮已确认知乎原草稿管理页面受创作者中心准入引导阻塞；不能据空列表或昵称变化声明旧草稿不存在。

升级现有实例会中断当前 v20 的连续观察；保留旧证据，在新固定 release 启动独立 48 小时窗口，不累计旧窗口。保持公开发布和创作调度暂停。
