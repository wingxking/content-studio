# 任务工作台与插件一致性升级

目标：一个任务管理每期内容、资料、平台版本、交付和记录。保留文章与视频独立业务身份，继续使用现有 Supabase、LocalFS、pgmq、pg_cron 和角色 worker。

## 已实现的结构

- 主导航：工作台、任务中心、发布管理、资料库、设置；旧内容与执行链接解析回真实任务和期次。
- 任务详情：概览、内容、资料与素材、发布、记录。首次生产归属固定保存，重新调研作为原期次的新执行与修订。选题衍生与独立复制分别建关系。
- 新建文章/选题：创作目标、资料与要求、执行与交付三步。视频保持显式创建、脚本与渲染。
- V2 按账号配置待审、草稿、自动发布；兼容 V1 配置及历史授权哈希。证据生产流程继续要求人工公开发布，能力不足的自动目标不自动改送草稿。
- 逐修订、逐账号预检；持久发布批次沿用现有队列，命令重放返回原批次，租约校验及已绑定交付支持重启恢复。未知提交仍需对账。
- 资料采集、任务关联、标签和归档。追加附件不改写已固定证据；用于后续生产需要明确选择。
- 插件 2.0.10 固定采集、任务、账号三页，与工作台共享状态文案和设计变量。独立 UI 通道使用原桥进程与端口的 `/ui/connect`；V1 执行请求与防重复日志保持原协议。
- 运行环境保持现有唯一 OrbStack 实例；没有增加常驻服务、数据库或调度所有者。

## 接口与边界

`/api/workspace/task-index`、`task-context/:kind/:id` 提供聚合查询；分区按需读取。`deliveries/preflight` 无审批、派发及来源刷新副作用；实际执行再次检查指纹和领域约束。`delivery-batches` 持久保存逐项结果，已受理不等于已发布。

插件内部 API 只接受无浏览器 Origin、匹配内部 Host 及桥服务密钥的请求；命令采用白名单。资料和回执链接不包含配对凭据，插件不获得数据库或发布服务密钥。

迁移为增量结构。原稿/视频/渲染身份、旧修订和交付哈希不重写。已有真实账号、暂停状态与未知提交不因升级自动改变。
