## 使用入口与运行边界

- 唯一工作台入口：`http://127.0.0.1:4310`。
- 唯一代码 checkout：`~/x/content-studio`，本轮未新增 worktree。
- 唯一 Docker 引擎：OrbStack。Content Studio 只有一个主工作区和一个应用运行时。
- 应用使用一个 Kubernetes namespace `content-studio-k8s`；Supabase、pgmq、pg_cron 继续由同一引擎内的原 Compose 数据服务运行。
- “一个环境”指一个引擎、一个主实例、一个操作入口。API、worker、模型、配音、渲染、资料服务按职责隔离容器；不能把一个 Kubernetes 应用等同于一个容器。
- 私有数据目录继续为原 `.docker-k-acceptance`。保留它的物理路径，避免移动素材、授权和发布日志。目录名称是历史名称，不代表另有一套验收服务。
- 主实例数据只保留一份权威来源：Supabase 业务状态与 LocalFS 素材。备份不参与运行。

## 用户操作

1. 首页查看创作环境；首次使用按“模型 → 首篇内容 → 平台”继续。
2. “新建内容”填写主题并选择目标平台；研究来源等设置按需展开。先运行一次，再决定是否启用定时生产。
3. “草稿与发布”检查主稿、平台稿与质量报告；编辑后需要重新审批。重新研究操作依据原任务生成新修订，并保留已有修订历史。
4. 配置页分别控制定时生产和公开发布。开启生产不等于授权公开发布；平台草稿也不等于已发布。
5. 视频需要显式创建与渲染，可独立于文章；横竖版、不同平台账号可共享同一不可变渲染文件。
