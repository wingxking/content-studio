# Content Studio Web 工作台设计方案

调研与代码核查日期：2026-10-10，Asia/Singapore。状态：**设计方案，尚未实现本次新增能力**。本文件落实用户要求；当前实现见 [现有进度](progress-and-architecture.zh-CN.md)，技术方案见 [本地与生产架构](web-technical-architecture.zh-CN.md)，一手资料见 [同类产品调研](research-web-workflows-2026-10-10.zh-CN.md)。

## 1. 产品结论

建议采用“任务 → 热点问题 → 内容项目 → 原稿 → 平台稿 → 可选视频稿 → 发布记录”的工作台。每个内容项目是所有版本、素材和交付历史的共同入口。用户在 Web 完成业务操作；本地 Codex 是执行引擎，第二阶段替换为模型 API，界面与内容关系保持一致。

不能证明存在一款适合所有账号、地区和预算的“全球最好”产品。对本项目最合适的组合是：借鉴 Planable 的编辑、预览和版本体验，StoryChief 的原文再利用，Feedly 的发现与筛选、ContentStudio 的生产与排程，保留本项目已有的发布证据与恢复机制。差异化重点是**原稿和平台稿的可追溯同步、人工微调保护、选中素材真正参与生成**。

先完成本地第一阶段，再实施第二阶段。下文生产架构是迁移设计，不代表已部署或已获各平台发布权限。

## 3. Web 页面与主要交互

| 页面 | 主要内容 | 核心操作 |
| --- | --- | --- |
| 工作台 | 待选问题、待合并稿件、进行中的生成、到期发布和账号阻碍 | 直接进入待办对应稿件；以待办为中心，不堆虚构统计 |
| 热点任务 | 任务名称、prompt、来源/地区/语言、时间、时区、素材、输出上限 | 创建、编辑、暂停、立即运行；预览下 5 次执行时间 |
| 热点收件箱 | 按任务和执行批次分组的问题卡 | 查看来源、收藏、忽略、选择一个问题创建内容项目 |
| 内容库 | 每个项目的原稿、各稿状态、视频数量、最近更新时间 | 搜索、过滤、打开项目、归档、从历史版本另建项目 |
| 内容编辑器 | 左侧项目版本树；中间编辑/平台预览；右侧 AI 指令与素材 | 改原稿、改某个平台、选择段落调优、查看差异、同步、审批 |
| 视频工作室 | 独立脚本、分镜、场景素材、旁白、字幕、封面、成片 | 手动创建稿件、改脚本、预览、渲染、重渲染、选择发布目标 |
| 素材库 | 上传/生成的图片等，标签、来源、尺寸、用途、引用项目 | 上传、选择、裁切派生、搜索、查看引用、归档 |
| 发布中心 | 日历/列表、账号、内容快照、发布状态和回执 | 排程、暂停、取消、处理权限问题、对账、查看真实链接 |
| 历史与效果 | 编辑、AI、素材、发布及指标时间线 | 版本比较、恢复为新版本、导出；看真实指标和成本 |
| 账号与设置 | 各账号身份/权限、品牌和模型设置、本地 worker 状态 | 重连、设置语言/风格/预算、查看本机是否在线 |

编辑器不把所有平台的长稿平铺在一个表单。默认一次编辑一个对象，可打开“原稿 / 当前平台”对照。移动端优先查看和轻量修改；复杂分镜与差异合并优先桌面。

### 3.1 热点任务

表单包含：名称、发现 prompt、主题范围、受众、包含/排除关键词、来源列表、地区、语言、新鲜度窗口、每天/每周/一次性的用户时间、IANA 时区、输出数量 1–20、单次预算、任务素材、启用状态。高级表达式放在折叠区域，用户无需写 cron。

示例 prompt：

> 寻找过去 24 小时值得向独立开发者解释的 AI 产品与工具变化。优先正式发布和实际案例，过滤纯融资消息与重复转载。把每个事件写成一个可回答的问题，列出来源和它对目标读者的影响。最多返回 12 个问题。

Scheduler tasks must compose their task-specific instructions with `buildDiscoveryPrompt()` from `src/core/content-prompts.ts`. The shared editorial exclusions apply before ranking; excluded or uncertain subjects do not become questions or articles. Use the selected platform profiles and [researched growth guidance](content-growth-guidance.md), then compare real audience-quality metrics rather than promise promotion. [Prompt exports](content-prompt-workflows.md) are implemented; the custom scheduler remains planned.

prompt 决定筛选和问题表述；真实来源连接器决定能访问哪些数据。修改 prompt 不会自动获得社交平台数据权限。任务保存时生成配置修订；已开始执行的批次继续使用当时的配置和素材快照。

默认“仅生成问题”。采集任务不会默认写长文、生成视频或发布。每轮可返回 0–20 条，不为凑够 20 条制造问题。每日 08:30 只是表单示例，不替用户创建真实定时任务。

### 3.2 每个任务的热点问题

每张卡显示：问题、事件摘要、为什么值得写、发生时间与采集时间、涉及地区、来源数量和链接、可验证程度、与 prompt 的匹配原因、是否已写过、建议角度。热度显示可追溯信号和各地区差异；数据缺失显示未知，不冒充全球总榜。

处理顺序：采集 → 标准化时间/来源 → 同一事件跨语言去重 → 提取有来源的事实 → 按任务筛选排序 → 生成问题 → 校验与封顶。问题关联事件 ID，同一任务中的同一事件默认一个问题；需要多个角度时用户手动展开。失败来源与缺失证据单独显示，不能把部分抓取成功报告为完整覆盖。

点“创作”后可修改角度、细化 prompt、受众/语言、目标账号、品牌风格和素材。先补齐能支撑写作的资料，再生成原稿。证据不足时保留问题和缺口，不能凭 RSS 标题补事实。

### 3.3 原稿与平台稿

每个项目有一个当前原稿，以及不可变的原稿历史版本。原稿包含标题、摘要、正文结构、事实/来源引用、用图建议。生成链路必须先持久化原稿，再使用这个确定版本生成各平台稿；某个平台失败可单独重试。

平台稿在生成前选择目标账号与内容类型：短帖、线程、图文、长文、视频发布文案等。适配要求包括语言、字数计算方式、标题、链接、标签、图片比例/数量和该账号实际能力。平台规则要版本化，显示校验时间与官方依据；统一的 300 字符字段上限不是各平台规则。

视频平台可以先有标题/说明等发布文案和“待创建视频”状态。**仅选择 YouTube / TikTok 等目标不创建脚本、分镜、音频或 MP4。** 图文卡生成也应为明确操作，用户上传的图片可以直接作为配图。

### 3.4 在 Web 给 Codex 下指令

右侧提供任务范围选择：“原稿 / 当前平台 / 所选平台 / 当前视频稿 / 选中段落”。输入框、素材选择器、保留项和“生成修改建议”组成一次结构化请求。例如：

- 原稿：“结合这两张产品截图补充操作步骤，保留引用，控制在 1000 字。”
- 小红书：“保留我改过的标题，开头更直接，加入这张图里的功能说明。”
- Reddit：“降低营销语气，补充技术限制，保留来源，不添加购买链接。”

模型产生修改建议与差异。用户接受全部或部分变更后创建新修订；拒绝建议不影响现稿。首次精细生成可以直接形成未审批草稿；之后针对已有稿件的自由指令默认先展示差异。进度、取消、重试、错误和模型使用记录均在 Web。可保存品牌/任务/平台 prompt 模板，但每次运行保留实际 prompt 修订和选中素材 ID。

自由指令限定在内容对象内，不让网页通过文本直接执行任意终端命令。新闻、网页与图片 OCR 内容均作为待核对资料，不能改变执行权限。

## 4. 原稿更新后的同步规则

用户要求“自动更新”和“独立微调”，需要同时维护**自动适配结果**与**人工编辑结果**。不能每次直接重生成后覆盖平台稿。

| 平台稿情况 | 原稿更新后的行为 |
| --- | --- |
| 未被微调、自动跟随 | 按新原稿重新适配，创建新稿修订，显示待审核 |
| 设置了长期风格要求 | 以新原稿 + 平台风格要求重新适配；仍需检查事实与限制 |
| 改过独立字段，例如标题 | 自动生成新的正文等未锁字段；保留标题；标出受事实更新影响的锁定字段 |
| 对正文作了自由微调 | 保存新自动稿，与旧自动稿、当前编辑稿三方比较；有冲突进入待合并 |
| 整版暂停跟随 | 保留现稿，显示“基于原稿 rN，原稿已到 rM”；允许手动同步 |
| 已发布或已有成片 | 历史快照不变；生成新草稿/过期提示；不自动修改远端作品或重新渲染 |

自动跟随是自动产生并保存新版草稿，不是自动审批或自动发布。原稿自动保存时先保存编辑状态；用户点击“保存并同步”提交原稿新版本后自动触发适配，无需逐个平台重新下指令，避免每敲一个字都调用模型。

三方比较对象：B = 上一次自动适配稿；L = 当前平台稿；N = 根据新原稿得到的新自动稿。字段未编辑时可替换；完全不重叠的确定性变更可以合并；同一段落或事实的修改必须展示冲突。大模型重写导致的语义差异不能由字符串 diff 保证正确，AI 合并结果仍为待审核建议。受保护的事实更正不应被“锁标题”永久忽略：保留微调同时标出陈旧事实并阻止受影响稿件排程。

生成任务绑定原稿版本与平台版本。任务完成时如果用户又改了原稿或平台稿，结果进入候选历史而非覆盖新内容，显示“基于旧版本生成”。同一平台的连续同步任务可合并等待队列，保留已执行历史。

示例：原稿 r3 的数字从 10 改为 12。小红书标题已微调，Reddit 未微调。Reddit 自动生成 r4；小红书保留标题，更新未锁内容，对冲突或旧数字给出差异；原有发布记录仍引用旧快照。用户无需再复制粘贴四次。

审批粒度应从整包改为“平台稿修订 + 目标账号 + 素材版本 + 规则版本”。单独改小红书不必作废无依赖变更的 Reddit 审批。提交新原稿版本的同一事务必须立即标记受影响稿件过期/同步中、作废其审批，并把尚未提交的发布任务暂停为待审核，然后再入队适配；不能等模型更新完才停止旧稿发布。带关联事实缺口的锁定稿也暂缓。派发前再次检查稿件的原稿/事实依赖版本与当前指针，防止同步期间误发旧稿；已经提交的任务继续按原快照对账。首版保守地将所有依赖该原稿的稿件视为受影响，只有证明依赖未变化后才能缩小失效范围。

## 5. 独立视频稿与制作流程

用户点击“创建视频稿”后，才从一个确定原稿版本或指定平台稿版本派生 `video_project`。内容包括：视频目标/时长/比例、开头、旁白、场景与字幕、每个场景的素材引用、声音设置、音乐、封面、发布标题与说明。脚本是一份独立可编辑稿件，并非 YouTube 文案字段里混入的 90–130 词旁白。

先生成脚本/分镜并审阅，再选择“渲染视频”。模板图文视频、上传镜头剪辑、AI 生成镜头是不同制作模式；不能把字幕卡 MP4 宣称为生成了真实场景视频。后者使用专门的视频提供商，按片段记录任务、费用、失败和结果。

同一视频项目可有竖屏/横屏/短版输出；平台版保存对具体 render ID 的引用。原稿变更只提示视频稿需要同步；脚本修改提示现有成片过期，**默认不自动重渲染、不自动新增费用**。用户决定更新脚本与重做哪些场景。已发布视频快照保持可回看。

## 6. 素材从上传到使用

建立一个可复用素材库，所有页面使用同一选择器。上传后返回稳定的 `assetId`，而不是向界面泄露绝对路径。

每个素材保存：文件名、类型、尺寸、摘要、标签、来源/使用权备注、校验哈希、原始文件与派生文件、创建方式、所属工作区、引用关系。内容图片可分配角色：“供理解参考 / 要出现在文章中 / 视频场景 / 封面 / 品牌标识”。“选中参考图”必须真的传入支持图片的模型，不能只把文件名放进 prompt。

任务选择素材后，运行时冻结素材 ID/版本；临时上传、从库选择均可。热点任务的图片用于理解产品或主题背景，不作为全球热度凭证。调优选择的截图可以提供视觉/OCR信息，文章输出和分镜引用具体素材。原文件保持不可变；裁切、标注、缩略图和转码生成新派生项。

素材页可查看“用于哪些任务、原稿、平台稿、成片和发布”。仍被发布快照引用的素材不能被普通删除破坏历史，可归档或在明确清理流程中处理。生产素材走私有存储与限时访问；上传校验实际文件格式、尺寸和容量，不只检查扩展名。

## 7. 历史、发布和效果

保留三类独立历史：编辑/AI 修订；运行和素材制作；发布及平台回执。恢复历史内容产生一个新的当前修订，不能删除后续历史。

发布记录保存准确账号、平台、稿件修订、素材哈希、审批、排程时间、实际提交时间、提供商/平台 ID、真实 URL、可见性/处理状态和证据来源。区分已排程、已提交、处理中、平台报告成功、待真人操作、结果未知和已核实。未知结果先对账，不能点“重试”就重复发帖。

日历同一天可以看各平台版本，但属于一个内容项目。指标为空表示未取得；在权限允许时接入平台分析。后续根据真实效果推荐选题/风格，不未经用户控制自动改写历史内容。

## 8. 分阶段实现与验收

| 顺序 | 可交付范围 | 必须通过的验收 |
| --- | --- | --- |
| L1：内容结构与素材 | 原稿/平台稿独立修订；历史恢复；素材库与选择器；拆分 Web 组件 | 单个平台修改不串稿；附件可复用；旧发布快照仍能访问；并发保存不覆盖 |
| L2：Web AI 编辑与同步 | 先原稿后适配；范围明确的 Codex 指令；修改建议；自动跟随与冲突 | 新原稿更新无微调稿；保留人工标题；同段冲突待处理；旧 AI 响应不覆盖新编辑 |
| L3：热点任务 | 时间/时区/prompt/素材；运行进度；收件箱 ≤20；问题转项目 | 暂停无新触发；同一时刻不重复；0/部分/失败如实显示；断线重启保留运行记录 |
| L4：独立视频 | 手动新建脚本/分镜、素材引用、渲染状态/版本 | 文稿生成不产生视频；脚本改动不自动渲染；能从 Web 完整预览和管理成片 |
| L5：本地完整工作流 | 发布中心接已有适配器与账号任务；获准真实发布/对账 | 用户在 Web 完成选题→精调→素材/视频→审批→获准发布→真实回执；保留既有恢复测试 |
