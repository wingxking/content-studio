# 2026-10-19 交互复核与优化

本轮将首次进入的默认页由完整选题表单改为首页。首页明确下一步，并展示当前模型、内容、账号和运行状态；不会因打开首页而启用调度、恢复发布或写入平台。

## 官方产品交互调研

调研日期：2026-10-19。以下是官方说明中的交互模式，并非对竞品全部功能的实测。

| 产品 | 官方交互模式 | Content Studio 本轮采用的改进 |
| --- | --- | --- |
| [Buffer Home](https://support.buffer.com/articles/using-buffer-home-WXHZkDiPYb) | 将首次使用步骤、快捷操作和近期内容集中在首页 | 用一个首页承接首次进入；创作、选题和视频入口清晰区分；已有用户可继续处理最近内容和任务 |
| [Postiz Quickstart](https://github.com/gitroomhq/postiz-docs/blob/main/general/quickstart.mdx) | 连接渠道、创作、排期、确认结果；保存草稿、排期和立即发布是不同操作 | 独立展示定时生产与公开发布状态；逐账号标明系统提交、同步草稿或复制发布，避免把登录或生成成功当成自动发布成功 |
| [WechatSync 官方仓库](https://github.com/wechatsync/Wechatsync) | 文章同步至目标平台草稿，支持浏览器扩展和 MCP | 明确“同步草稿，平台手动发布”；没有实际桥接能力时展示复制入口能力，不依据已登记账号推断草稿可用 |

## 已实现的界面改进

- `/` 为统一首页，品牌入口返回首页；保留原有内容、选题、发布、视频和设置路由。
- 首次使用路径为“准备创作模型 → 生产第一篇内容 → 选择发布方式”。未连接发布账号仍可生成、复制与导出内容。
- 首页读取实际模型状态和账号能力，展示最近内容与执行记录；读取失败单独显示，不用空白或成功标记掩盖错误。
- 导航使用“草稿与发布”“内容库”“执行记录”等直接名称，提供键盘跳转主要内容入口。
- 配置页先展示服务与模型等必需项；知识库、平台交付及验收等可选项集中折叠。配置检查通过不代表所有平台完成生产验收。
- 内容列表保留类型、平台与状态筛选；日期、任务和执行批次放入高级筛选。URL 中已有的高级筛选会显示其生效状态。
- 空内容库、未连接平台和无待分发内容均给出下一步入口。
- 实际浏览器走查发现运行开关不可达，已在配置页恢复独立的定时生产与公开发布控制。状态未知或读取失败时禁止操作；打开配置页不会改变开关。
- 新建内容默认保留研究来源和审校策略；来源编辑器、权重与预算折叠到“调整来源与研究设置”，降低首次创作需要面对的字段数量。
- 质量报告失效时，可明确请求“重新研究并生成新修订”：基于原任务要求产生新修订，保留当前修订记录，并要求重新审批。编辑未保存或存在并发冲突时禁止发起此操作；请求后展示实际任务进度及历史入口。
- 定时计划开关从高级设置移到执行时间旁；保存后的任务显示计划状态、下次执行时间和定时生产总开关状态，避免把“任务已启用”误读为当前正在调度。
- 原模型暂不可用时，已有任务保留模型选择，可以保存原配置、调整计划或停用；新建任务、替换模型、重新启用和立即运行仍要求可用模型。页面提供模型检查与重新读取入口，不会自动替换已保存模型。
- 重新研究失败或取消后，可“继续此次研究”，沿用同一运行编号和已完成步骤。进行中的研究隐藏重试入口，未保存的编辑禁止继续。
- 扩展断开时保留已存账号绑定的上下文，显示安全的扩展 ID 和桥接端口及恢复步骤；区分连接中断与平台退出登录。实际身份或扩展 ID 变化时提示先核对未确认任务再迁移，不自动重绑或重发。
- 配置页的折叠检查信息显示当前运行版本、构建时间与短源码指纹；缺少版本信息时明确显示暂不可用。
