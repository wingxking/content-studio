# Portable Docker runtime and delivery

Date: 2026-10-11. This record supersedes the native runtime target; previous publication evidence remains historical. All deployed services run in Compose. Only Docker/Compose, a shell, this repository and a private bind root are required on the host. No launchd, macOS speech, host Codex/Node/Supabase CLI, Keychain or fixed user path is required.

## Supported lifecycle

`sh scripts/docker.sh` builds a small operations container. Only that explicit lifecycle container mounts the Docker socket; application/model services never receive it. Commands accept `--root`, configurable Web/database/Supabase ports, and host UID/GID. Configuration and credentials remain in ignored private directories. `.dockerignore` excludes runtime data, credentials, dependencies and Git metadata.

An existing Supabase installation can be captured once using `capture --source-project content-studio-local --data-source /absolute/legacy-data --root /absolute/new-root`, after a verified backup and stopping only its identified source containers. Original named volumes and containers are preserved. This capture records private service configuration and cold database/storage bytes; it is migration tooling, not a clean installer.

Portable `backup --root /absolute/root --target /absolute/private-backup` pauses application work and owned cron, writes a full logical PostgreSQL dump plus roles, and copies Storage, LocalFS, artifacts, renderer/TTS caches and private state. Database, roles, configuration, credentials and private journals use AES-256-GCM with authenticated relative paths; the manifest hashes ciphertext. The separate 32-byte key defaults to `<root>/backup.key` and is never included in the backup. Transfer the key separately. Raw PGDATA is excluded, and backup destinations inside the bind root are rejected.

`restore --source /absolute/private-backup --key-file /absolute/separate-key --root /absolute/new-root` verifies every file, starts a new database, restores roles and logical data, and leaves publication/scheduling paused. It restores extension-owned GraphQL functions/grants and pgmq queue/archive records omitted by normal pg_dump. It archives pending engine messages, clears leases, preserves terminal history and checkpoints, and marks only interrupted work for explicit operator retry. Submitting jobs require reconciliation; their IDs and approval snapshots remain unchanged. Default restore omits Codex authentication/cache and delivery credentials/session journals, creating UUID-only protected journal markers in delivery storage and the shared catalog. Use `--restore-private` only for an explicit private transfer. Then run `database`, `migrate`, `build`, `start` and `status` against that root. Restore assigns a new Compose project and configurable ports; it never starts an old instance simultaneously. Model authentication can be re-established independently. A first-machine clean install without an existing captured Supabase configuration remains an explicit limitation.

Linux Codex uses its own `/auth` bind directory and pinned CLI. Authenticate inside the model container with `codex login --device-auth`; do not mount an entire host home, browser profile or Keychain. `/readyz` verifies CLI authentication separately from process `/healthz`. A successful structured execution with image input is required for model acceptance. New machines establish their own account authorization.

## Contracts implemented

- LocalFS content keys, finalized asset registry, bounded tus upload chunks/restart recovery, and immutable historical path aliases. Original approval hashes, historical snapshots and upload IDs are never rewritten.
- Independent article/video subjects and operations. Video revisions, selected footage, render identity/bytes, publishing metadata and exact account bind immutable approval; no article is mandatory.
- Tiptap rich article document with citations and stable asset references, maintained Markdown export, safe HTML, Sharp image adaptation and preserved manual platform edits.
- Container CPU Kokoro speech, MoneyPrinterTurbo rendering, persisted stage hashes/receipts, captions, media probing and explicit cancellation. No automatic render follows article edits.
- One runtime pgmq engine/pg_cron schedule owner with role admission, bounded retries/dead letters and existing lease fencing. pg-boss remains an isolated development spike pending its full cutover gate.
- Shared article/video account serialization, streamed SHA-256, bounded 8 MiB YouTube chunks and same-session explicit continuation. Unknown external outcomes require reconciliation rather than another upload.

## Optional browser draft companion

The `draft-bridge` container uses the application image to speak the existing WechatSync extension protocol. It has no Supabase key, model authentication, browser profile, cookie mount or platform API implementation. Its public companion socket is bound only to `127.0.0.1:19527` by default; the Docker wrapper accepts `--draft-bridge-port` and defaults an isolated restore to 19528. The resulting `STUDIO_DRAFT_BRIDGE_PORT` is stored in the private Compose settings. Internal HTTP port 8915 is not published. Process health can pass before pairing; an unconfigured or disconnected companion cannot submit work.

Pair only the intended owner Chrome profile. Install the reviewed WechatSync extension, find its 32-character extension ID in `chrome://extensions`, then enable **CLI / MCP connection** in its settings to obtain its Token. Enter the ID and Token in Content Studio's local companion setup; paste the returned connection URL into the extension's server-address field and refresh the connection check. The URL includes a private pairing key: keep it out of chat, tracked files and screenshots. The connection requires the exact extension Origin and pairing key; a second browser cannot replace a live connection. Changing the pairing configuration disconnects the previous session. Keep the browser open and signed into each intended platform; this optional companion does not establish unattended Docker-only browser execution.

Configuration lives under the private bind root at `delivery-private/draft-bridge/config.json`, mounted at `/data/draft-bridge`. Only API has write access; the delivery worker and gateway mounts are read-only. The Docker wrapper creates the directory with mode 0700 for the configured host UID/GID when capturing, restoring or starting an instance. The file is atomically replaced with mode 0600. It follows the existing encrypted `delivery-private` backup boundary and is omitted by a default restore; pair the intended browser again, or use the documented explicit private-transfer restore. Do not put this directory in the shared asset tree.

The reviewed upstream source is [WechatSync a98e428](https://github.com/wechatsync/Wechatsync/tree/a98e42865387285afcc027c61836488748f3b30f), extension version 2.0.9. This gateway allows only article drafts for `weixin` (WeChat Official Accounts), `zhihu` and `bilibili`, one target per submission. It permits account checks and bounded image transfer, and exposes no extraction, shell or public-publish method. Browser login and an installed extension do not replace platform permission or account-specific acceptance. Other advertised upstream platforms, including private adapters, are outside this reviewed contract.

The upstream extension reports a draft ID/URL but has no read-draft or idempotent retry method. Inspect the returned draft in the native editor before marking it verified. Disconnects, malformed replies and timeouts after dispatch retain an unknown outcome; inspect the original draft before retrying. WeChat editor URLs can contain a session token and must be sanitized before persistence. Gateway transport tests use a fake extension and do not count as a real-platform remote-draft acceptance.
