# Content Studio 品牌与任务交付复核

本轮保留工作区既有改动，优先公众号、知乎和B站专栏。产品目标是“本地内容生产、品牌一致、异常时介入”；平台能力、执行结果与真实公开发布分别记录。

## 竞品与官方通道（2026-10-17 复核）

| 对象 | 官方资料展示的能力 | 本产品取舍 |
| --- | --- | --- |
| [Wechatsync](https://github.com/wechatsync/Wechatsync) | 网页采集、图片迁移、多平台同步、MCP；默认保存草稿 | 保留 GPL 来源和适配能力，业务状态、账号授权、任务恢复由 Studio 管理 |
| [蚁小二](https://xueyuan.yixiaoer.cn/article/46522) | 多账号分发、提前排期与定时发布 | 优先少数平台的可验证闭环；不把营销覆盖数量视为账号授权证明 |
| [Postiz MCP](https://postiz.com/mcp) | AI 工具接入、排期、分发和数据读取 | AI/MCP 本身不构成品牌优势，突出本地权威、来源及修订追溯、账号级防重 |
| [Buffer](https://buffer.com/publish) | 渠道时区、定时发布、平台文案、自动与提醒发布 | 统一交付选项，并明确显示自动、草稿和人工操作的边界 |

[知乎官方项目](https://github.com/zhihu/ZhihuPublisher)要求申请 OpenAPI 凭证，其现有流程包含预览后确认；尚未将其当成无人值守合同接入。[B站官方平台](https://openhome.bilibili.com/doc)列有专栏管理能力，但需身份认证、应用审核及用户授权。[公众号官方发布文档](https://developers.weixin.qq.com/doc/service/api/public/api_freepublish_submit)本轮未能完整读取，不能据此断言本账号具有接口权限。未新增猜测的网页发布接口。

在线实例只读能力核验：公众号/B站尚无登记账号，知乎具备草稿连接；三平台 `automatic=false`。过去官方扩展的知乎验证不能替代本轮修改版的真实验收。

## 实现

- 主应用、扩展、图标、帮助和安装包统一为 Content Studio；附上 GPL 来源及对应源码包。移除上游营销/更新/评价入口，清理旧公告和更新缓存，网络遥测保持禁用。
- 不再向任意网页注入旧 `$poster/$syncer` 桥。受保护的 Studio WebSocket 草稿协议与扩展内部界面继续使用；页面提取和 DOM 预处理保持原职责。
- Studio 模式首页显示连接、三个支持平台和最近任务日志，不在打开弹窗时扫描所有账号；完整业务历史仍以 Supabase 为准。
- 新任务默认使用可编辑品牌配置；固定读者、语气、术语、主色及封面规范版本。规范进入共享生成提示和执行快照。封面预览是设计规范，不冒充已经生成的图片。
- 内容任务提供自动草稿、规则授权后自动发布、人工发布。生产和发布时间分开；重复任务的日期依据原生产 occurrence，而不是完成或重试时间；拒绝不存在或重复的 DST 时刻。
- 服务端生成授权 ID、完整配置 hash 和账号身份 hash。停用任务、撤销授权、改配置/品牌或变更真实账号都会阻止旧授权的公开提交；旧任务不自动获得授权。新建/克隆/手动选题不接受客户端伪造的服务端授权。
- 生成结果必须保持初始修订、来源和平台内容完整，不能有待处理研究警告，平台版本须保留来源链接。模型评估不是独立审核。发布前复核授权和现有媒体/修订/账号规则。
- 授权的 API 目标进入现有定时队列。生成未赶上发布时间则转待处理；90 秒仅容纳现有分钟调度器的投递延迟，超过窗口不追发。结果不明先对账，不自动重发。
- 三个优先平台当前没有已验证的官方公开适配器，自动任务降级为草稿请求并提示人工发布；草稿失败或缺少账号/配对时明确阻塞，不标为成功。
- 用户明确审阅后可接管尚未提交的自动任务，历史保留原授权；已有远端身份或需对账的提交不被替换。

发现任务继续自动生产/送草稿；公开自动授权本轮限定明确选题的内容任务。批量自动选题后直接公开发布尚未开放。文章/视频边界、旧文件、hash 和审批算法保持原值，没有新调度引擎。

## 验证与剩余门槛

已执行：严格双端类型检查；主应用 388 项测试（387 通过、1 历史 macOS 用例跳过）；扩展 50 项；跨工程真实 Supabase/pgmq 集成 8 项全部通过；主应用和 MV3 生产构建；回滚事务中的授权重放/撤销 SQL；隔离原生草稿降级、幂等、撤销和过期窗口；模拟 API 到点提交、回执核验与未知结果不重发；两次真实 HTTP API 进程重启保留品牌和授权，撤销状态继续生效。

浏览器验收通过：新建并保存双时间/账号/品牌任务；品牌修改要求重新授权；封面规范可编辑。隔离工作区和夹具文件在测试后清理，旧视频修订与媒体 hash 保持一致。FFmpeg 完整解码原有验收 MP4 通过；本轮不宣称重新渲染。

`tests/automation-burn-in.ts --confirm-isolated-burn-in` 提供最长 48 小时重复隔离验收，每轮使用随机工作区并清理，只测试模拟模型/平台与真实本地数据库，不启用业务调度或真实公开发布。启动和完成状态需分别记录；未跑满不能标记通过。

本轮扩展产物：`extension/artifacts/content-studio-v1/dist/`、二进制 ZIP 及对应源码 ZIP。源码/构建通过不等于设备 k 已加载并配对。真实三账号草稿、平台官方权限、48 小时稳定性仍是独立验收门槛。
